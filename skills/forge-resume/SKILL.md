# /forge resume — 会话恢复

> **触发方式**：用户在新会话中输入 `/forge resume`
> **职责**：在新会话中快速恢复之前的工作上下文，避免重复理解和重新开始
> **输出路径**：无文件输出，仅终端展示恢复的上下文

---

## 1. 概述

`/forge resume` 通过五个问题快速重建工作上下文——正在解决什么问题、当前在哪一步、已知发现、下一步是什么、有什么阻塞。它从 `.forge/` 状态文件中自动提取答案，让开发者在新会话中无缝继续之前的工作。

**核心原则**：恢复上下文的成本应该接近零。开发者不应该花时间回忆"我上次做到哪了"。

---

## 2. 数据来源与五问题恢复

### 前置：读取 status.md

**数据来源**：`.forge/status.md` + `.forge/knowledge/sessions/`

在回答五个问题之前，**先读取 `status.md`** 获取全局上下文，然后检查会话层知识：

| 字段 | 用途 |
|------|------|
| `current_task` | 确定当前任务主题，用于定位对应的 plan/progress/findings 文件 |
| `tier` | 确定当前档位（轻量/标准/全量），用于判断下一步应该执行哪个命令 |
| `phase` | 确定当前阶段，用于判断是继续 build 还是进入 review/test/ship |
| `updated` | 上次更新时间，帮助开发者判断中断了多久 |

**会话层恢复**：

1. 首先检查 `.forge/knowledge/sessions/` 中是否存在 `*-interim.md` 文件。
   如果存在，说明上次会话在 build 阶段中途中断，interim 文件包含最新的执行上下文。
   
2. 如果存在 interim 文件：
   - 读取其中的"进度快照"→ 注入到问题 2（当前在哪一步）
   - 读取其中的"关键发现"→ 注入到问题 3（已知发现）
   - 读取其中的"异常记录"→ 注入到问题 5（有什么阻塞）
   - 读取其中的"活跃约束"→ 在恢复后的首次 Restatement 中重新注入

3. 如果不存在 interim 文件，按原有逻辑读取正式的会话日志（与当前任务匹配的会话文件中的上下文快照：关键决策点、中间状态、恢复提示），作为五问题恢复的补充信息。

**恢复后の首次 Restatement**：

当 `/forge resume` 恢复上下文后，如果用户确认继续 build，
在派发第一个 Subagent 之前**立即执行一次 Restatement Checkpoint**（不等计数器归零）。
这确保恢复后的执行从一个完整的上下文状态开始。

**输出**（在五问题之前展示）：

```
🔄 Forge 会话恢复

📊 全局状态
  任务：<current_task>
  档位：<tier>（轻量/标准/全量）
  阶段：<phase>
  上次更新：<updated>
```

### 问题 1：正在解决什么问题？

**数据来源**：`.forge/plans/<topic>.md` 的 Objective 章节（`<topic>` 从 `status.md` 的 `current_task` 推导）

读取 Plan 文档中的 Objective 部分，提取当前任务要解决的核心问题。

### 问题 2：当前在哪一步？

**数据来源**：`.forge/status.md` 的 `phase` 字段 + `.forge/progress/<topic>.md` 中状态为"进行中"的任务

先从 `status.md` 确定当前阶段（如 `build`），再从 Progress 文档找到具体的进行中任务。如果 phase 是 `review`/`test`/`ship`，说明 build 已完成，应该继续对应阶段而非回到 build。

### 问题 3：已知发现是什么？

**数据来源**：`.forge/findings/<topic>.md`

读取 Findings 文档，提取研究阶段和执行阶段的发现。如果 findings 为空，输出"暂无发现"。

### 问题 4：下一步是什么？

**数据来源**：`.forge/plans/<topic>.md` 的 Task Breakdown 章节

从 Plan 的任务列表中，找到当前进行中任务的下一个任务。

### 问题 5：有什么阻塞？

**数据来源**：`.forge/progress/<topic>.md` 中的"阻塞"章节

读取 Progress 文档中的阻塞项列表。如果无阻塞，输出"无阻塞"。

## 4. 自动定位

恢复完成后，自动定位到上次中断的任务：

1. 读取 Progress 中的"进行中"任务。
2. 如果有进行中的任务 → 定位到该任务。
3. 如果没有进行中的任务 → 找到第一个未完成的任务。
4. 如果所有任务都已完成 → 提示进入下一阶段（review/test/ship）。

**定位后的行为**：

- 展示定位结果，等待用户确认后继续执行。
- 用户确认 → 从定位的任务继续 `/forge build`。
- 用户拒绝 → 等待用户指示。

## 5. 边界情况处理

### 5.1 无 `.forge/` 目录

```
⚠️ 未检测到 .forge/ 目录。没有可恢复的工作上下文。
请运行 forge init 初始化项目，或运行 /forge 开始新任务。
```

### 5.2 无 Plan 文件

```
ℹ️ 未找到计划文件。当前没有活跃的任务计划。
运行 /forge 开始新任务。
```

### 5.3 无 Progress 文件

```
🔄 Forge 会话恢复

━━━ 1. 正在解决什么问题？ ━━━
<Plan Objective>

━━━ 2. 当前在哪一步？ ━━━
ℹ️ 未找到进度记录。任务可能尚未开始执行。

━━━ 3. 已知发现 ━━━
暂无发现

━━━ 4. 下一步是什么？ ━━━
<Plan 中的第一个任务>

━━━ 5. 有什么阻塞？ ━━━
无阻塞

✅ 上下文已恢复。建议从 Task 1 开始执行。
```

### 5.4 所有任务已完成

```
🔄 Forge 会话恢复

━━━ 1. 正在解决什么问题？ ━━━
<Plan Objective>

━━━ 2. 当前在哪一步？ ━━━
✅ 所有任务已完成

━━━ 3. 已知发现 ━━━
<Findings 内容>

━━━ 4. 下一步是什么？ ━━━
所有 build 任务已完成。下一步：/forge review

━━━ 5. 有什么阻塞？ ━━━
无阻塞

✅ Build 阶段已完成。建议运行 /forge review 进行评审。
```

Task 4/5：实现下载链接过期逻辑（预估 4 min）

━━━ 3. 已知发现 ━━━

- 现有的文件存储服务支持 signed URL，可直接用于过期链接
- 导出文件大小平均 2MB，无需分片
