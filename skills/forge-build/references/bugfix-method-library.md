# Bugfix Method Library

根因六分类 + 日志升级模板，analyze 阶段按此分类根因，apply 阶段引用对应修复策略。

## Root Cause Taxonomy

### 逻辑错误

- **典型模式**: 条件分支遗漏、边界判断错误、运算符误用
- **识别方法**: 对比期望行为与实际行为，定位分叉点
- **修复策略**: 修正条件/运算，补充遗漏分支

### 状态错误

- **典型模式**: 状态机转换缺失、过期状态引用、竞态下的状态不一致
- **识别方法**: 追踪状态变量生命周期，检查所有写入点
- **修复策略**: 补充状态转换约束，添加状态守卫

### 数据错误

- **典型模式**: 数据格式假设错误、空值未处理、类型转换隐式失败
- **识别方法**: 检查数据流边界，验证输入假设
- **修复策略**: 添加数据验证，修复格式处理逻辑

### 并发错误

- **典型模式**: 竞态条件、死锁、异步操作未 await
- **识别方法**: 检查共享资源访问，追踪异步调用链
- **修复策略**: 添加同步机制，修正异步流程

### 配置错误

- **典型模式**: 环境变量缺失、配置值硬编码、默认值不当
- **识别方法**: 检查配置加载链路，验证运行时配置值
- **修复策略**: 修复配置加载逻辑，补充缺失配置项

### 缺防御

- **典型模式**: 未处理异常、缺少输入校验、缺少 null/undefined 检查
- **识别方法**: 检查外部调用边界，查找未保护的代码路径
- **修复策略**: 添加防御性检查，补充异常处理

## Log Escalation Template

修复未生效时的日志调试升级流程。

### Round 1 — 关键路径日志

```
在以下位置添加 console.log / console.error:
1. 根因假设涉及的函数入口
2. 关键条件分支
3. 数据转换前后
→ 运行复现步骤 → 分析日志 → 调整修复 → apply + verify
```

### Round 2 — 扩大范围

```
扩大日志范围:
1. 上游调用链
2. 并发操作时序
3. 状态变更序列
→ 重新分析 → 调整修复 → apply + verify
```

### Exhausted — 回退

```
2 轮后仍失败:
→ 回 analyze 阶段重新做根因分析
→ 原假设可能错误，重新定位
→ 清理所有添加的日志代码
```
