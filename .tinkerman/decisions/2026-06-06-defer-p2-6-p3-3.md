# ADR: Defer P2-6 (Large Module Splitting) and P3-3 (Manifest-Driven Packaging)

- Date: 2026-06-06
- Status: accepted
- Scope: audit-remediate-p2p3

## Context

Code audit identified two large-scale refactoring items:

- **P2-6**: 4 modules exceed 1000 lines (grill.ts 1141, error-recovery.ts 1130, review.ts 1118, decide.ts 1109)
- **P3-3**: `build-dist.sh` uses hand-copied file lists instead of manifest-driven packaging

## Decision

Defer both items to separate PRs after P2/P3 remediation is merged.

## Reasoning

1. **Risk**: Each 1000+ line module has 16–117 test files referencing it. Splitting risks breaking tests and introducing regressions in a PR that also touches security, CI, and documentation.

2. **Scope isolation**: The P2/P3 PR already includes 7 changes (HMAC, command counts, smoke tests, deps, CI jobs). Adding large refactoring would make review and rollback harder.

3. **Independent value**: Both items deliver value independently and don't block the current audit remediation.

4. **P2-6 approach**: Split by functional domain (parser, policy/evaluator, renderer, IO adapter) following the existing pure-driver pattern. Each module gets its own PR.

5. **P3-3 approach**: Create a `dist-manifest.json` that declares all files/directories, then update `build-dist.sh` to consume it. Add contract test verifying manifest accuracy.

## Consequences

- P2-6 and P3-3 remain as open audit items
- Future PRs should reference this ADR for context
- No release-blocking impact (both are P2/P3)
