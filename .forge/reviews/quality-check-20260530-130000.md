## Layer 2: quality-check Review

### P0 Issues

### P1 Issues

**P1-1: Unhandled JSON.parse on CLI argument — `knowledge-hook-dispatch.mjs:77`**
```js
const event = JSON.parse(json); // line 77, no try-catch
```
The `--from-path` branch (line 55) wraps `dispatchKnowledgeEvent` in try-catch. But the `--event` branch calls `JSON.parse(json)` directly on raw CLI input without any error handling. Malformed JSON causes an unhandled `SyntaxError` crash. This is inconsistent with the fail-silent design used elsewhere in the hook.

```yaml known-failure
pattern_id: json-parse-cli-arg-no-try-catch
severity: P1
first_seen_commit: a55ae7540a9b68ad4c78a011cb2db8d222a29961
signature: "JSON.parse on raw CLI --event argument without try-catch in knowledge-hook-dispatch.mjs. Malformed input causes unhandled SyntaxError crash, inconsistent with fail-silent design in --from-path branch."
fix_required: "Wrap JSON.parse(json) in try-catch with stderr diagnostic and process.exit(1)."
```

### P2 Issues

**P2-1: Unbounded cache growth in `writeEventCache` — `knowledge-hook-dispatch.mjs:123-138`**
Every PostToolUse event appends to the knowledge cache with no eviction. The cached `result` object contains the full dispatch result which may include substantial content. Over time, this grows without bound. Same concern applies to `persistViolations` in `record-evolved-rule-violation.mjs` (flagged by security-check as P3).

**P2-2: Missing file permissions on violation cache write — `record-evolved-rule-violation.mjs:108`**
```js
writeFileSync(cachePath, JSON.stringify(updated, null, 2), "utf-8");
```
No explicit `mode: 0o600`. Other cache writes in the same diff (`inject-evolved-rules.mjs:168`, `plugin-data-path.mjs:127`) correctly use `{ mode: 0o600 }`. Inconsistency suggests an oversight.

**P2-3: Shallow integration tests for knowledge-cache and rule-violations-cache**
Both `test/scripts/knowledge-cache.test.ts` and `test/scripts/rule-violations-cache.test.ts` only test that `getCachePath()` resolves to the correct path. They do not test that the actual caching functions (`writeEventCache`, `readKnowledgeCache`, `persistViolations`) work correctly at runtime. This is an integration test coverage gap.

**P2-4: Unnecessary wrapper function `getKnowledgeCachePath()` — `knowledge-hook-dispatch.mjs:109-111`**
Single-use trivial wrapper that just calls `getCachePath("knowledge-cache.json")`. Adds indirection without value.

### P3 Issues

**P3-1: Unused import `statSync` — `knowledge-hook-dispatch.mjs:11`**
`statSync` is imported from `node:fs` but never used in the file.

**P3-2: Duplicated `if (cacheFilePath)` guard — `inject-evolved-rules.mjs:148, 161`**
The null check on `cacheFilePath` appears twice in `readEvolvedRulesWithCache`. Could be consolidated into a single block.

**P3-3: Misleading shebang on library module — `plugin-data-path.mjs:1`**
The shebang `#!/usr/bin/env node` is present on a library module that only exports functions and has no CLI logic. Should only appear on entry-point scripts.
