# 决策：全项目代码精简与重构

## 1. 背景与目标

对 Forge 全项目做等价 refactor：移除冗余、简化内部实现、清理死代码与重复，**保证对外行为完全不变**。

**Reframing 结论**：目标=综合（体积 + 可维护性 + 技术债）**按 ROI 排序**；激进度=**平衡**（死代码 + 去重 + 适度简化，每改动有测试保护）；执行=Full + **按模块拆子任务**。

## 2. Product — 价值与取舍

ROI 三准则：① 重复消除且触达面广；② 只动有 co-located 测试覆盖的代码（无测试先补测试）；③ 改动可逆性（纯函数先动，契约后动）。

**可维护性度量**：用"每 PR 的 review P0/P1 回归数"对比基线，而非 LOC 删减量。

## 3. Technical — 架构与拆分方案（critic 修正后）

**关键修正**：architect 原结论"不存在大块死代码"被 critic 证伪——`src/deprecated.ts`（152 行 v2.4→v2.5 shim，唯一 caller 是测试类型断言，标注 v2.5.0 移除而当前 v3.4.0）才是最大死代码。

**修正后的拆分方案**（每项独立 feature 分支，按 ROI/风险排序）：

| # | 子任务 | 空间 | 风险 | 说明 |
|---|--------|------|------|------|
| 1 | **删除 deprecated.ts** | 大（152 行） | 低 | 死 shim，契约已到期；连带改 `barrel-file.test.ts` 移除 deprecated 断言 |
| 2 | **barrel re-export 清理** | 中 | 低 | 删幂等 re-export（如 `error-recovery/index.ts:12`）；**连带更新 barrel-file.test.ts 的 `toHaveLength(140)` 魔数** |
| 3 | **error-recovery (1200)** | 中 | 低 | 纯函数、barrel 隔离；types.ts 25 export 主战场 |

## 4. Security — 威胁建模

风险中等可控。**误删清单**（review 必查）：路径 normalization（worktree-manager/sandbox-policy）、allowlist/case 分发（forge-dispatcher/、scripts hooks）、input reject/severity、audit+HMAC（audit-log.ts）、命令构造纯函数（execFileSync 不得改字符串拼接）。

**去重陷阱**：两实现一严一松必须留严的；`*-parity.test.ts` 不得删除。

**STRIDE**：Tampering/Repudiation/Elevation=中，其余低。

## 5. Critic 修正（已采纳）

1. **scripts/ 是 dist 真实 consumer**：check-frozen/init/bump-version 等 10+ 脚本直 `import dist/src/*.js`。**约束：精简不得重命名/移动被 scripts import 的 src 路径**（否则 dist 路径漂移破坏 hooks 运行时）。
2. **测试是重构对象，非纯安全网**：`barrel-file.test.ts:185 toHaveLength(140)` 与精简目标冲突；改此魔数前须核对公开 API 契约 ADR（ADR-0002/0003）。
3. **去重仅限同构纯函数**：实测 `parseGitLog` 有 3 套不同签名/语义（recap.ts/fix-recovery.ts/git-scanner.ts），合并必改契约=违反行为不变。本次范围只合并签名语义完全同构者。
4. **deprecated.ts 补为优先项 #1**。

## 6. ADR Criteria（评估后续精简动作是否合规）

- 改动是否同步 `dist/src/**`（R6）？
- 删除函数前是否 grep + entry 双向核验无 production caller（R10）？
- 去重是否真删一边（R12），未留双 export？
- 是否触碰 ADR-0002（capability scope）/0003（单入口）/0004（skills collapse）/0007（agent teams）锁定边界？
- 安全 chokepoint 是否误删（R8）？

## 7. Veto / 非目标（绝对不动）

- MCP tool 名称/参数、CLI 退出码与 stdout、Bitbucket marker 正则/hash、`forge init` 产物——外部可观察契约
- 安全/门禁控制（state-file-locking、branch-protection、three-strike、sandbox）
- ADR 锁定边界（0002/0003/0004/0007）
- `*-parity.test.ts`、`test/security/*`、`adversarial-mcp-boundaries.test.ts` 等安全测试
- 新增 adapter/抽象层（与精简目标矛盾）
- 文档治理类内容（constitution/glossary/.claude/rules 即便冗余也非本次代码 refactor 范围）

## 8. 待用户裁决项

**deprecated.ts 删除**：虽标注 v2.5.0 移除且契约已到期、零业务 caller，但属"向后兼容 shim"，是否纳入本次删除范围需用户确认（见 decide 确认环节）。

## 9. 回归防护（每个子任务）

1. `npx tsc --noEmit && npx vitest run`（R11，缺一不可）
2. `npm run dist:resync` 同步 dist（R6）
3. 删函数前 `grep -RIn 'import.*<fn>' src/` + 核 entry（R10）
4. 子任务结束 `npm run check` 全量门禁
